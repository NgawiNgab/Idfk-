## Acquisition → classification → rendering

| Stage | Evidence in the supplied source |
| --- | --- |
| Acquisition | **CONFIRMED:** Apollon's `Block_getRenderLayer` detour receives a block and position, reads a type pointer through `Block::getBlockTypeClassCustom()`, and treats an ABI-dependent field of the type as a `std::string`. It filters by that string and camera distance, then adds a record if the position is not already in `renderOresESP`. All return paths forward the original render-layer result. See `app/src/main/jni/main.cpp:1238–1277` and `app/src/main/jni/hook_classes.h:22–37`. Discovery is driven by calls to this hook, not a full chunk or palette scan. |
| Identity and configuration | **CONFIRMED:** `allowToXrayRender()` selects by exact `tile.*` strings and category switches; it includes categories beyond ores, such as barrels. `GetOreColor()` maps names to fixed ImGui colors (`app/src/main/jni/hook_utils.h:162–234`). A record stores a copied name, integer and floating-point coordinates, and a color (`app/src/main/jni/variables.h:120–125`, `app/src/main/jni/variables.h:144–145`). The master and category switches are persisted by `saveConfig()` and `loadConfig()` (`app/src/main/jni/variables.h:272–289`, `app/src/main/jni/variables.h:478–495`). This path does not classify by runtime ID or decoded block state. |
| Refresh | **CONFIRMED:** `NormalTick` uses the local player's `getDimensionBlockSource()` to re-query **cached coordinates**, not discover new ones. It drops out-of-range records, disallowed cached names, or records whose current lookup reports air. The predicate does not reclassify a non-air replacement. After enough removals, it signals `rebuildChunkGeometry`; `ClientInstance_onTick` passes that request to the renderer wrapper, and `InMainMenu` clears the vector. See `app/src/main/jni/main.cpp:463–499`, `app/src/main/jni/main.cpp:943–950`, and `app/src/main/jni/main.cpp:993–1009`. The source also applies a separate `FullBright` patch when `xrayDefault` is active (`app/src/main/jni/main.cpp:335–341`); forwarding the layer result does not mean the entire toggle leaves game rendering untouched. |
| Presentation | **CONFIRMED:** `BeginDraw()` obtains view, camera, and FOV data and calls `RenderOreESP()` on the ImGui background draw list during HUD rendering (`app/src/main/jni/menu.h:1121–1140`). `RenderOreESP()` projects the eight corners of a unit cube, rejects the box if a corner fails projection, and draws colored lines, omitting edges based on other cached positions. It does not query terrain depth in that routine (`app/src/main/jni/menu_utils.h:664–793`, `app/src/main/jni/hook_utils.h:283–304`). The Java `Platform2.onDrawFrame()` calls native `step()`, which renders ImGui via its OpenGL backend (`app/src/main/java/com/mojang/minecraftpe/platforms/Platform2.java:8–24`, `app/src/main/jni/main.cpp:352–373`). This is a screen-space overlay, not an alteration of the terrain mesh by the collection hook. |

## Comparison and limits

- **CONFIRMED — different data sources:** [BedrockTools Light Overlay](intake.md#bedrocktools-reference) explicitly samples a coordinate box and submits camera-relative meshes in a world-render hook. Apollon collects candidates from render-layer calls and draws projected lines in ImGui. BedrockTools Connected Glass also classifies names, but uses its own `Block::fullName()` layout and adjusts face texture coordinates. These are different use cases and do not establish interchangeable layouts or render contracts.
- **CONFIRMED — source-level risks:** The source deduplicates insertion by a linear position scan and checks neighbors by scanning the same vector for each projected entry, giving worst-case quadratic overlay work. The key is position alone, not dimension plus position. Revalidation calls `currentBlock->isAir()` without an explicit null check when the cached name is still selected. These are code properties, not measured failures. Relevant locations: `app/src/main/jni/main.cpp:473–499`, `app/src/main/jni/main.cpp:1258–1273`, `app/src/main/jni/menu_utils.h:668–725`.
- **UNKNOWN — target native contracts:** The reference offsets, position representation, string layout, lookup behavior for unavailable positions, and the render/tick thread and lifetime contracts were not checked against a game binary. The reader and writers shown above share `renderOresESP` without visible access synchronization; their actual scheduling was not measured. No generalized chunk or palette decoder was identified in the reviewed block-outline path.

This trace is source-only. See [XRAY-001](xray-001-evidence.md) for the later user-run report and its separate binary evidence. Apollon's Android layouts and hooks are not verified for the target.
