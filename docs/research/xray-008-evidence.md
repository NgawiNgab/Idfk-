# XRAY-008 — World access and camera findings

**Decision:** Stop the broad static batches here. The report corroborates an update-to-region path, a mutable chunk lookup, and a camera-data path. None is yet a live binding. Use copied data for the portable outline core; keep native world and camera access inactive until validated separately.

## Scope

User-run `zaphkiel_out-8.txt`: 14,161 bytes, 398 logical lines; SHA-256 `9f3f5b8a63ba57169fdfc8b54e37387995b2b3ab68ed09827a60a653aa474753` (**report only**). All eight sections match the [XRAY-008 input](xray-008-batch/zInput.txt). The cache path, byte count, and segment metadata match XRAY-001–007 (`zaphkiel_out-8.txt:3–18`). All 340 instructions in these windows agree after formatting normalization with the same windows of the [separate Drive ELF](intake.md#binary-intake). No new download, agent-run Zaphkiel, or live-world test. This is selected static agreement, not identity of the cache file or loaded module.

## Next implementation boundary

- **Host-only:** The [portable core](../../README.md#host-only-outline-core) classifies exact copied names, keeps unavailable distinct from a read of air, bounds the cache and render batch, and clips using an explicit synthetic projection convention. It uses no game addresses, status numbers, or native layouts.
- **Device integration (not tested):** Establish which module is loaded and whether the installed Preloader supports the HUD APIs. Verify an existing read path that neither generates chunks nor outlives its ownership window, plus coherent view/projection and viewport sampling for the main render pass. Then run controlled offline checks using known ore, non-ore replacements, valid air, unavailable positions, and world exit/re-entry. The report alone does not authorize an offset-based build.

No XRAY-009 input or startup change is needed at this point. Another broad disassembly run would not settle the live integration gates.
