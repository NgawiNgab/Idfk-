# XRAY-008 — World access and camera data

**Status: report received and compared.** All eight windows agree with the separate Drive sample; see the [XRAY-008 findings](xray-008-evidence.md). This batch followed [XRAY-007](xray-007-evidence.md) and checked where the game obtains a world region on an update path, what state its chunk lookup can modify, and where a render path gets camera data. It did not add camera controls or repeat ore-name and palette probes.

## Why these addresses

The addresses below are **leads from the separate Drive sample**, not validated bindings on the installation. The [recorded Drive SHA-256](intake.md#binary-intake) was rechecked. Read-only `.text` scans of the pinned BedrockTools [`NormalTick`](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/core/memory/Signatures.cpp#L18), [`RenderLevel`](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/core/memory/Signatures.cpp#L47), and [`GetFov`](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/core/memory/Signatures.cpp#L37) patterns each found one aligned match: `0xaf5e7a0`, `0xb7a38a0`, and `0xb7c8e64`, respectively. The descriptions below also use sample call sites and ELF relocations rather than assuming those labels and the reference offsets are correct. The agent did not run Zaphkiel or download a new binary. The scanned cache and loaded module identities remain unverified.

## Original run (complete)

The handoff was for one run on the same instance/build, using [this input](xray-008-batch/zInput.txt) and the [focused config](xray-004-batch.md#original-run-instructions), without a startup change. [`range<>`](https://github.com/NgawiNgab/Zaphkiel-RE/blob/ba566e6eea4b71c544edd21d9c79d988c5791508/README.md#L67-L74) disassembles file windows; it does not execute the functions. The returned `zaphkiel_out-8.txt` contains `targets: 8` and no unresolved windows.

**Decision after comparison:** The matches do not verify loaded-module identity, the producer behind the indirect acquisition, safe thread/lifetime for an independent reader, or viewport/projection in a live frame. Keep native access inactive on unverified builds. No rerun or additional static batch is requested.
