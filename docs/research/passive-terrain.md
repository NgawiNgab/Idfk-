# Passive terrain probe — 1.26.62 ARM64

**Status:** Separate experimental LeviPack, default off. Static trace and host fixture coverage, **no device result yet**. This is a coverage test, not working ore outlines. Use a disposable offline world, with other native mods and the one-block behavior pack off. No game reinstall is needed.

## Run on the device

1. On [PR #1](https://github.com/NgawiNgab/Idfk-/pull/1), download **passive-terrain-probe-arm64** from the successful **Build ARM64 HUD test** run that includes this diagnostic. Unzip the artifact and import `passive-terrain-probe.levipack` in LeviLauncher. Exit Minecraft before changing packages. Enable **Passive Terrain Probe** in the launcher and disable **Ore Outlines HUD Test** and other native mods for this run. There are no cyan/gold boxes in the probe.
2. In a new Creative superflat Overworld with cheats enabled and multiplayer off, set up the two controls. Do this **before** starting capture. The second diamond is enclosed by stone on all six sides. Both are in the same 16×16×16 section; the nonzero chunk origin also tests world rather than chunk-local XYZ.

   ```text
   /tp @s 21 102 -12
   /fill 16 99 -16 31 99 -1 stone
   /setblock 20 100 -12 diamond_ore
   /fill 27 99 -5 29 101 -3 stone
   /setblock 28 100 -4 diamond_ore
   ```

3. Save and exit to the title screen. Turn on **Passive Terrain Probe** in the Mod Menu (this just shows the HUD), open its settings, and press **Start capture**. If the Mod Menu is unavailable at the title screen, instead travel far from the test section in the same world (e.g. `/tp @s 2048 150 2048` in Creative), wait for that area to load, and start capture there. If the probe reports a check or attach failure, stop and send the exact message. Do not try to bypass it.
4. Reenter the world or return to the site normally (`/tp @s 21 102 -12` if you staged far away). Let terrain finish loading. **Do not change the blocks during the capture.** Press **Freeze and show report**, close the menu, and send the three HUD lines or a cropped screenshot. This stops collection and restores the dispatch pointer. No ADB, Zaphkiel, or behavior pack is needed.
5. If the exposed control matched but the enclosed control did not, remove only the roof block (`/setblock 28 101 -4 air`) **after** freezing. Repeat steps 3–4 with a fresh capture. If both matched in the original covered trial, no uncovered repeat is needed. If asked to compare a replacement later, use a separate fresh capture; a frozen result reports what was seen during a window, not the block's current state.
6. Switch off the probe and exit Minecraft when finished. If the game crashes or the HUD says it could not detach cleanly, exit, disable the probe in the launcher, and report what happened; do not keep retrying attachment. No saves besides the test world are needed.

| Frozen result | Interpretation |
| --- | --- |
| `builder visits observed`; both `diamond marker` | The selected native terrain callback supplied both controls during this ordinary build window, including the enclosed diamond if the cover stayed intact. This is the first-pass success condition. |
| `builder visits observed`; exposed `diamond marker`, enclosed `not visited`; then both match uncovered | The probe saw an ordinary pass and the exposed control. It did not see the enclosed position at this observation site in the covered trial. The uncovered repeat controls for the second point and coordinate convention. This is not proof that every engine pipeline omits buried ores. |
| `builder visits observed` without a matching exposed control | Some builder calls ran; the target section and binding have not been positively validated. An `air key / fallback` cannot establish loaded air or missing ore. `other block key` and `unknown block key` also do not prove culling. |
| `no builder visits observed` | No qualifying call reached the probe in this window. An already meshed area, a different build path, or a scope mismatch can give this result. Not evidence against buried ore coverage. |

## Static evidence and scope

This is the independently reassembled [Drive sample](intake.md#binary-intake), not Apollon's binary. All six part hashes, ZIP CRC, ELF SHA-256, and GNU Build ID were rechecked. A previous user-reported loaded Build ID matched; the runtime gate checks it again and compares exact instruction windows and a relocated pointer. The full game ELF and reference archive are not shipped.

- Apollon passively [collects from a layer call](apollon.md#acquisition--classification--rendering), forwards the original layer, and does not need a world scan for discovery. In the target, the `0xaa5bf70` tessellation selector takes a block and flag, **not** a position. The downstream `0xaa5d444` path has block and XYZ at the `0xaa62ef4` call, but comes after graphics/shape selection; its hits would not prove pre-cull coverage.
- The builder at `0xa9c4b14` (incoming call `0xa9d0dd0`) creates a `BlockSource` via `0xa9f663c → 0x1036e680`. The constructor stores the `0x13d6e328` vtable address point. Its `+0x10` entry (`0x13d6e338`) has a file-backed `R_AARCH64_RELATIVE` relocation to `0x10371934` in GNU RELRO.
- The first per-cell loop derives XYZ from the builder's section origin at input `+0x38..+0x40`, normally up to origin + 16 on each axis (`0xa9c517c..0xa9c51ac`). It can clip to bounds or early-out for a section. At `0xa9c5530..0xa9c5554`, the virtual call has `x0 = BlockSource*`, `x1 = &XYZ` (three signed 32-bit words at `sp+0x1c8`), returning the resolved `Block` reference in `x0` to `0xa9c5544`. The resolver does Y bounds, shifts X/Z by four to find the chunk, and converts to local coordinates *inside* the original lookup. These are world block coordinates at the call site. This ABI is two pointer arguments and a pointer return on ARM64, not a reflection API or freely callable world reader.
- The builder checks the returned block's air key. On the non-air branch, `0xa9c5614` calls layer selection `0xb847cec` with block, region and the same XYZ. The low byte of its result is used in later dispatch. There is no per-face eligibility check between the virtual read and this layer call. The probe observes the earlier read, leaving the entire layer/shape pipeline alone. It deliberately does **not** observe general lookups or claim every terrain path reaches this loop.
- Both the next key comparison (`0x109f4950 → 0x10919454 → 0x134ef05c`) and [the independent name trace](xray-006-evidence.md#names-hashes-and-the-coordinate-fallback) follow `Block + 0x68` to a type, then access its key at `+0xc8`. The published `diamond marker` is the copied first word matching `minecraft:diamond_ore`, not a runtime ID, string, or general classifier. The air key can be returned by a fallback. No SDK block layouts or Apollon addresses are used.

## Attachment and lifetime

- The probe is compiled separately with `BUILD_TERRAIN_DIAGNOSTIC=1`; the original HUD artifact contains no native detour. Registering, loading or showing the module does not attach. Only the **Start capture** button runs preflight. Only one matching already-loaded game mapping, exact R-X bytes, and the original aligned pointer in a non-executable GNU RELRO span qualify. An `RTLD_NOLOAD` handle must identify that same game image. There are no scan-and-try fallback addresses.
- The [pinned Preloader inline API](https://github.com/LiteLDev/preloader-android/blob/cc08b40a31471d3e2dedb267f5f17b28da2b0604/src/pl/memory/Hook.cpp#L73-L109) does not provide a worker-drain contract. Its bundled ARM64 GlossHook trampoline also uses the Android-reserved `x18`. The probe does not use it, does not patch executable instructions, and does not need to assume worker quiescence. It changes exactly one naturally aligned dispatch pointer with a checked atomic exchange on a verified private non-executable data page; it restores the page's read-only permissions. A protection restoration error attempts rollback and refuses further recording if unresolved. No other mods or memory editors should run alongside it.
- The slot is shared by `BlockSource` instances, so there is a forwarding cost while attached even for unrelated caller addresses. The original function receives the original two arguments exactly once; its result is returned unchanged. Only exact return PC `0xa9c5544` is eligible for capture. Game and observer code remain mapped through process exit even after detach, so a worker holding the old pointer still has a valid destination. See the [Android linker flags](https://android.googlesource.com/platform/bionic/+/refs/heads/main/android-changes-for-ndk-developers.md) and the package's `DF_1_NODELETE` check; no hot library unload is promised. Freeze, disable and unload disarm before attempting restoration; they do not wait on or release engine objects.
- The hot path does not allocate, log, submit HUD draws, edit the world, issue extra lookups, or retain pointers. Two coordinate-specific evidence flags and a builder-seen bit are latched in one atomic word for each window. Late observations with a prior token are discarded. Test points are only report filters, **not** requests to the engine. There is no runtime world/dimension token here; use one offline Overworld for each trial. No render cost or lifecycle acceptance on the installed launcher has been measured yet.
