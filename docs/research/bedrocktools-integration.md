# What this build takes from BedrockTools

Reference: [`NgawiNgab/BedrockTools` at `c03d3ae`](https://github.com/NgawiNgab/BedrockTools/tree/c03d3ae0c9022557de0acdf0d94e373e0b9e0579). This project does not depend on the BedrockTools runtime or copy its game bindings.

| Area | What BedrockTools does | What this project does |
| --- | --- | --- |
| Build and package | [CI](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/.github/workflows/build.yml#L9-L32) installs NDK r28c and builds an Android `arm64-v8a` release with xmake. The [build target](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/xmake.lua#L21-L60) runs a [Python ZIP packager](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/scripts/package_levipack.py#L24-L73) for a root `preload-native` manifest, its `.so`, and optional assets. | Use the same NDK, ABI, package shape and CI artifact flow, with [CMake](../../CMakeLists.txt) for this single target as in the [launcher example](https://github.com/LiteLDev/LeviLauncher-Android/blob/d544df8cafab731ba7686dfb88951602f13293ef/examples/full-cpp-mod/CMakeLists.txt#L83-L119). Link against the launcher's pinned Preloader revision. The [launcher build](https://github.com/LiteLDev/LeviLauncher-Android/blob/d544df8cafab731ba7686dfb88951602f13293ef/app/build.gradle#L70-L91) uses API 28 as its minimum and `c++_shared`. The pack includes neither Preloader nor a C++ runtime, game library, or reference-client asset. |
| World reads | [Light Overlay](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/modules/visual/lightoverlay.cpp#L123-L133) caches a player pointer and position on tick. Its [render hook](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/modules/visual/lightoverlay.cpp#L260-L304) follows dimension and region offsets, traverses a coordinate box and uses a solidity test or a pointer comparison against an out-of-range lookup. [`BlockSourceGetBlock`](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/modules/visual/lightoverlay.cpp#L417-L426) is resolved by a game signature, not a public engine API. | Reuse the value-level coordinate and filter design, not the cached game pointer, air heuristic, or render-thread scan. [XRAY-008](xray-008-evidence.md) confirms mutable chunk-cache state and branch-specific status tests; it does not prove availability or ownership. The CI module has **no world adapter**. |
| Block identity | [Connected Glass](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/modules/visual/connectedglass.cpp#L124-L183) classifies names through its offset-based [`Block::fullName()`](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/include/bedrocktools/sdk/render/Block.hpp#L9-L18) wrapper. | Match exact copied block-name values in the host core. The HUD test enters two synthetic samples; it does not call a native name accessor or interpret runtime IDs. |
| Rendering and lifecycle | [Light Overlay](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/modules/visual/lightoverlay.cpp#L324-L365) draws camera-relative geometry with the game tessellator. [Cinematic Camera](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/modules/visual/cinematiccamera.cpp#L152-L197) instead gets the launcher HUD size and replaces or empties its draw batch. Its [frame event](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/core/GameHooks.cpp#L284-L289) comes from a swap-buffers detour. [`PL_REGISTER_MOD`](https://github.com/NgawiNgab/BedrockTools/blob/c03d3ae0c9022557de0acdf0d94e373e0b9e0579/src/main.cpp#L4-L17) registers the lifecycle. | Register a default-off HUD test with `PL_REGISTER_MOD`. Project at most 24 lines from fixture data, convert RGBA to launcher ARGB, submit via the public API on menu changes, clear on toggle-off, and clear/unregister on disable or unload. No frame hook, backend patch, or live camera copy. Resample HUD size on the next menu change after resize. |

## What the CI result means

A green [build](../../.github/workflows/build.yml) verifies the host unit tests, Android compilation/linking, lifecycle export, ELF dependencies, 16 KiB alignment and archive layout. It does **not** establish that the installed launcher exports this API, that its display matches the synthetic fixtures, or that Minecraft can be queried safely. See the [offline smoke checklist](../../README.md#offline-hud-smoke-test) before trying to connect a block reader.
