## Independent comparison — downloaded sample only

**CONFIRMED:** `readelf -lW` and an independent read-only scan of the hash-verified downloaded ELF were used here, not a second Zaphkiel run. The seven `PT_LOAD` triples (file offset, ELF virtual address, memory size), two executable ranges (`0x0–0x13686ff0`, `0x14318000–0x14319000`), and byte count agree with the report's header (`zaphkiel_out.txt:3–15`). Scanning only the file-backed executable `PT_LOAD` bytes for all 32 fixed bytes of the 68-byte pattern yielded exactly one hit at file offset **`0x10371934`**, ELF virtual address **`0x10371934`**. Those numbers coincide because both bases of the containing segment are zero. The scan used the exact pattern recorded at `zaphkiel_out.txt:21` after confirming its fixed bytes and wildcards against the reference source.

This is agreement on the observed segment layout and one candidate location, not a comparison of either complete file. It does **not** identify the installed library, show identical layouts elsewhere, or validate a native call. Installed target binary identity remains **UNVERIFIED**.
